# 聊天显示与酒馆插件兼容方案

## 本分支已实现的范围

- 预设条目右侧提供启用开关，点击正文打开详细编辑。预设与附带 `extensions.regex_scripts` 在一次设置更新中保存；报告列出规则数量及跳过项。
- 删除聊天的拍照、照片、草图及音视频附件入口，移除 OCR 选择、提示词设置和自动识别执行路径。角色卡 PNG、角色头像和背景图片导入保留，旧图片消息仍可查看。
- 聊天菜单、模型设置与角色基础设置提供上下文和最大回复 token 数。聊天菜单只改当前会话，模型/角色设置改角色默认值；旧会话未记录新字段时兼容原有继承行为。
- 自定义数值没有界面档位上限，不绕过提供商的实际限制。上下文为空时跟随模型标注值；最大回复为空时不指定输出上限，由提供商决定。
- 请求展开宏和提示词后估算 token 数，预留指定的回复额度及工具定义预算，必要时从最早的完整对话轮次移出请求。静态设定、最新一轮和工具链保留，历史记录不删除；固定内容已经超过预算时明确报错。摘要请求不会静默移出待总结消息，超出预算时提示增大上下文或分段总结。估算不能代替服务端 tokenizer。
- 闭合的 HTML 代码块直接在聊天内以 WebView 渲染，混合正文和多个代码块保持原顺序。未闭合代码块仍显示源码；普通代码语言保持代码显示。未更改原有网页资源域名设置。

本轮按用户要求不生成 APK。下述缓存与文字方案尚未实现。

## 缓存命中率

当前消息统计仅显示“缓存 tokens / 输入 tokens”，没有明确百分比。缓存字段默认值为 0，也无法可靠区分“服务未返回”与“返回且未命中”。

建议：

1. 回复下方默认显示 `缓存命中 82% · 8,200 / 10,000 tokens`，与输入、输出、耗时保持同一行视觉层级；文字不用低透明度压暗。
2. 详情列出输入总数、缓存读取、缓存写入（接口支持时）、输出和当前提供商。命中率只用读取缓存量除以规范化后的输入总量，不把缓存写入算成命中。
3. 数据模型记录“是否收到缓存字段”。未返回时显示“未返回缓存数据”；明确返回 0 才显示 0%；分母为 0 不计算百分比。旧消息缺少标记时不伪造“确定为零”。
4. 会话汇总采用 `已知缓存读取总量 / 对应的已知输入总量`，不平均每条百分比，并标注统计覆盖范围。工具循环中的不同请求累计，单次流式 usage 快照不重复累计。
5. 不把本地前缀稳定度当成服务端真实命中率，不推算未提供的费用或节省比例。

## 背景与文字可读性

当前正文跟随应用主题。深色主题配白色背景图、且助手气泡默认关闭时，浅色正文会难以阅读。HTML 卡片还有作者自己的 CSS，需与原生聊天正文分别处理。

建议：

- 提供“自动 / 深色字 / 浅色字 / 自定义”，设置全局默认，并允许角色单独覆盖；字号、引用色、统计文字一起预览。
- 默认使用可调透明度的文字底板。自动模式依据最终文字底板选择前景色，正文目标对比度至少 4.5:1。这样比仅对整张背景图取平均亮度可靠，能应对明暗混杂的图片。
- 保留全屏背景显示，底板透明度可调，提供可选的轻微描边/阴影辅助；不把阴影作为唯一保障。
- 原生聊天主题不强行覆盖 HTML 卡片的作者样式。WebView 无明确前景/背景颜色时使用成对的可读默认值；另设可选的“卡片可读模式”，说明会改变卡片原外观。

建议先做正文颜色和底板，再做背景自动识别与 HTML 卡片的特殊覆盖。

## 插件能兼容到什么程度

目前不能把任意 SillyTavern 扩展仓库直接安装进原生 Android 应用。能复用网页引擎，不代表具备 SillyTavern 宿主接口。

| 类型 | 当前边界 | 建议 |
| --- | --- | --- |
| 角色卡、世界书、预设、正则 | 已有导入、转换及兼容性报告 | 继续以实际导入和执行结果报告兼容程度 |
| 消息内 HTML/CSS/JS 前端 | WebView 可渲染；远程资源服从现有域名配置 | 优先支持状态栏、选项面板、纯前端互动卡 |
| 酒馆助手函数 | 当前桥接只覆盖部分消息读取、变量读写、基础 slash 指令 | 建立带版本的能力清单，按接口逐项补齐，不伪装完整 TavernHelper |
| MVU | 现有桥接仅提供部分数据读写，不是完整 MVU 脚本和事件框架 | 选定代表性角色卡验证实际所需接口，再适配事件、更新和依赖 |
| 普通酒馆扩展 | 常依赖 SillyTavern DOM、jQuery、模块路径、getContext、事件总线及扩展设置 | 不能直接安装；选择插件逐个提供原生等效功能或明确兼容层 |
| Node/服务器插件 | 当前无 SillyTavern Node 宿主；本项目已去掉 Web 服务与工作区运行时 | 本轮不引入运行环境；有远程服务的可单独通过接口接入 |

建议顺序：自动渲染 → 函数能力查询与兼容性报告 → 常见消息/变量/事件接口 → 指定 MVU 卡验证。不要先做一个“可安装所有酒馆插件”的入口，却没有相应宿主环境。
