# 设置首页的酒馆化方案（设计提案）

目标：在设置首页直接看到角色卡、世界书、预设、正则，不再通过“通用设置 → 扩展 → 提示词 → 标签页”寻找。本文是待实施方案；本分支尚未重排设置首页。

## 首页结构

| 顺序 | 分组 | 直接显示的入口 |
| --- | --- | --- |
| 1 | 酒馆资料 | 角色卡、世界书、预设、正则规则、快捷回复 |
| 2 | 聊天与叙事 | 用户人设、提示词与作者备注、上下文与记忆、显示与消息行为 |
| 3 | 模型与连接 | 默认模型、模型提供商、联网搜索 |
| 4 | 数据与应用 | 备份与恢复、存储管理、外观与网络、通知 |
| 5 | 高级与关于 | 技能（Skills）、MCP、请求日志、关于 |

第一组采用现有 Material 3 Expressive 的 CardGroup 分段行，使用明确的中文名称、图标、数量与简短状态。外观设置移到应用偏好中，不抢占首页第一行。

## 四个核心入口

- **角色卡**：复用现有角色管理与卡片导入能力；提供搜索、新建、导入 PNG/JSON、编辑、导出和删除。面向用户以“角色”命名，已有普通助手和酒馆角色卡保留原数据。
- **世界书**：集中管理世界观条目，区分公共世界书与角色卡内嵌世界书，显示来源、条目数量与绑定情况。
- **预设**：单独管理酒馆提示词模板和顺序，不再混在世界书列表。显示导入兼容性报告；模型采样参数与提示词预设的适用范围分别说明，不把未实现的参数伪装成已支持。
- **正则**：集中管理正则组，明确标注全局规则和角色规则，以及作用于显示还是发送提示词，避免误把角色专用规则应用到所有聊天。

每个入口直接打开对应的管理列表，并在列表中提供新建、导入、搜索、编辑、导出和删除。角色页负责选择绑定的资料；设置首页管理资料库。修改绑定时继续遵循现有会话配置快照规则。

## 必须处理的数据兼容

SillyTavern 预设仍由 LorebookSerializer 转成 Lorebook；本分支已增加 WORLD_BOOK / PRESET 分类字段。新导入的预设直接归类，旧数据按明确的导入描述标记迁移，保留原 ID、条目、启用状态与角色绑定。编辑标题已按分类区分。设置首页与列表尚未正式拆分；无法自动判断的旧资料应在拆分时提供手动移动分类。

现有“模式注入”不能直接换个标题就当成完整酒馆预设；它需要与导入的提示词模板在新预设页中清楚区分。

## 默认助手删除（本分支已处理）

两个默认助手使用普通删除入口，删除后不会在下次读取设置时补回。有其他角色时可以把两个默认助手都删除；当前至少保留一个角色，最后一个会提示先新建或导入。删除当前角色会切换到剩余角色。原有删除确认继续说明关联聊天和记忆的处理。

## 验收标准

1. 打开设置首页即可看到四个核心入口，不需要进入扩展页。
2. 四个入口打开各自的管理列表，标题、内容与导入格式一致。
3. 世界书和预设不会变成两个指向同一混合列表的按钮。
4. 导入报告、角色绑定、历史聊天和会话配置快照保持兼容。
5. 旧默认助手删除后，重启应用和恢复新格式备份都不会让它们复活。
